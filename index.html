1 Architecture & Core Concepts

🔄

Internal Modifications

Cheat code is directly saved in the game's static files space. Injected into the process — easier detection but full access to game internals.

📡

External Modifications

Sit separately from the game and use Windows API features (or kernel drivers) to read/write memory data. Harder to detect, but limited to memory operations.

💡
Server-Side Limits: Damage calculation, loot distribution, and physics are validated server-side. External tools cannot bypass authoritative mechanics.
⚡
Unity-Specific: Mono/IL2CPP structure, managed object layouts, and native-to-managed bridges require offset translation.

Step 1: Professional Panel UI Development

A comprehensive guide to building beautiful panel-based user interfaces for desktop applications. This tutorial contains in-depth instructions, code snippets, and design best practices.

❓ Why does the UI matter? Isn't it just about functionality? ▼
A good UI improves usability, reduces errors, and makes your tool professional. While functionality is king, a clean interface helps you navigate features quickly. It also matters for distribution — people trust polished software.
❓ Should I use GUI or TUI? ▼
It depends on your use case. GUI (ImGui, Qt, WinForms) is better for visual overlays and user-friendly panels. TUI (Spectre.Console, ncurses) is great for headless servers or quick tools. Many devs use both — TUI for backend/debug and GUI for the main panel.
❓ What if I want to skip UI entirely? ▼
You absolutely can! A console application that runs silently in the background is perfectly valid. This step is here for those who want it — skip to Step 2 if UI isn't your priority.
🖼️ Windows Forms Application (.NET Framework)

Objective: Create a modern, visually appealing panel UI using WinForms and third-party libraries (Guna, Siticone).

🛠️ Tools & Libraries

  • Guna.UI2 WinForms (NuGet package)

📘 Detailed Implementation Steps

  1. Create a new Windows Forms App (.NET Framework) project in Visual Studio.
  2. Install desired UI library via NuGet Package Manager (e.g., Guna.UI2.WinForms, Siticone.Desktop.UI).
  3. Open the Toolbox. You will see new controls (Guna2Panel, Guna2Button, etc.). Drag a Guna2Panel onto the form to act as the main container.
  4. Set the panel's Dock property to Fill to occupy entire form, or create a side navigation panel by setting Dock=Left and adjusting width.
  5. Add child controls (buttons, labels, data grids) inside panels to design dashboard layouts. Use 'Bring to Front' / 'Send to Back' to manage layers.
  6. Customize appearance: Use Guna2Panel's BorderRadius, Shadow, FillColor (gradient). For Siticone, use SiticoneShadowPanel, SiticoneElipse, etc.
  7. Create smooth transitions: Use timers or animations to slide panels, change visibility, or build a hamburger menu.
  8. Implement responsive design: Anchor controls appropriately and handle resize events to keep panel layouts adaptive.
  9. For advanced UI, embed user controls, load forms in panel container using panel.Controls.Clear(); panel.Controls.Add(formInstance);
  10. Apply consistent themes: set global font, color scheme, and hover effects for buttons to give a modern feel.

Option 1: Using Keyauth.cc Commercial Service

Keyauth.cc is a powerful authentication and licensing system. It handles user login, hardware ID locking, expiry dates, and remote variables — no backend coding required.

Setup for C# WinForms

  1. Register an account at Keyauth.cc and create an application.
  2. Download the Keyauth .NET DLL from the developer section.
  3. Add the DLL as a reference in your WinForms project.
  4. Create a login form (or reuse the one from Step 1) and add the Keyauth logic.

using KeyAuth;

public partial class LoginForm : Form
{

    public LoginForm()

Option 2: Self-hosted Node.js Server + JWT Free & Full Control

If you prefer full control over user data and authentication logic, build a lightweight Node.js backend. It will expose REST endpoints that your panel UI (C# or Qt) calls over HTTP.

🖥️ Node.js Server Setup

  1. Initialize a Node.js project: npm init -y
  2. Install dependencies: npm install express jsonwebtoken bcryptjs cors dotenv
  3. Create server.js with the following structure:
JavaScript — Node.js Auth Server
const express = require('express');
const jwt = require('jsonwebtoken');
const bcrypt = require('bcryptjs');
const cors = require('cors');
require('dotenv').config();

const app = express();
app.use(express.json());
app.use(cors());

// In-memory user store (replace with real database)
const users = [];

app.post('/register', async (req, res) => {
    try {
        const { username, password } = req.body;
        const hashed = await bcrypt.hash(password, 10);
        users.push({ username, password: hashed });
        res.json({ success: true });
    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

app.post('/login', async (req, res) => {
    const { username, password } = req.body;
    const user = users.find(u => u.username === username);
    if (!user) return res.status(401).json({ error: 'Invalid credentials' });
    const valid = await bcrypt.compare(password, user.password);
    if (!valid) return res.status(401).json({ error: 'Invalid credentials' });
    const token = jwt.sign({ username }, process.env.JWT_SECRET || 'secretkey', { expiresIn: '1h' });
    res.json({ success: true, token });
});

app.listen(3000, () => console.log('Server running on port 3000'));

C# WinForms Client Integration

Use HttpClient to call the Node.js endpoints. Store the JWT token securely (e.g., ProtectedData or user-level storage).

C# — HttpClient Auth + Login Handler
using System.Net.Http;
using System.Text.Json;

public async Task<string> AuthenticateAsync(string username, string password)
{
    using var client = new HttpClient();
    var loginData = new { username, password };
    var content = new StringContent(
        JsonSerializer.Serialize(loginData), Encoding.UTF8, "application/json");
    var response = await client.PostAsync("http://localhost:3000/login", content);
    if (response.IsSuccessStatusCode)
    {
        var json = await response.Content.ReadAsStringAsync();
        var result = JsonSerializer.Deserialize<LoginResponse>(json);
        return result.token; // store this token
    }
    throw new Exception("Login failed");
}

// Then in your login button click:
private async void btnLogin_Click(object sender, EventArgs e)
{
    try
    {
        string token = await AuthenticateAsync(txtUsername.Text, txtPassword.Text);
        // Save token (Properties.Settings or secure storage)
        MessageBox.Show("Login successful!");
        MainPanelForm main = new MainPanelForm();
        main.Show();
        this.Hide();
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message);
    }
}

C++/Qt Client Integration

Use QNetworkAccessManager to send HTTP requests and parse JSON replies.

C++ — Qt HTTP Auth Client
#include <QNetworkAccessManager>
#include <QNetworkRequest>
#include <QNetworkReply>
#include <QJsonDocument>
#include <QJsonObject>

void LoginDialog::onLoginClicked()
{
    QNetworkAccessManager *manager = new QNetworkAccessManager(this);
    QUrl url("http://localhost:3000/login");
    QNetworkRequest request(url);
    request.setHeader(QNetworkRequest::ContentTypeHeader, "application/json");

    QJsonObject json;
    json["username"] = userEdit->text();
    json["password"] = passEdit->text();
    QByteArray data = QJsonDocument(json).toJson();

    QNetworkReply *reply = manager->post(request, data);
    connect(reply, &QNetworkReply::finished, [=]() {
        if (reply->error() == QNetworkReply::NoError) {
            QByteArray response = reply->readAll();
            QJsonDocument doc = QJsonDocument::fromJson(response);
            QString token = doc.object()["token"].toString();
            // Save token (e.g., QSettings) and accept dialog
            accept();
        } else {
            QMessageBox::warning(this, "Error", "Authentication failed");
        }
        reply->deleteLater();
        manager->deleteLater();
    });
}
📌
For subsequent API calls, include the token in the Authorization: Bearer <token> header.

🔒 Security & Design Best Practices

🔐

Security Essentials

  • Never hardcode secrets — use environment variables or secure config files
  • Hash passwords (bcrypt) when self-hosting — never store plain text
  • Use HTTPS in production to prevent token interception
  • Implement token refresh for long-running desktop sessions
🛡️

Hardening & UX

  • Add hardware locking (Keyauth) or device fingerprinting to prevent credential sharing
  • Provide visual feedback — loading spinners, password strength meters, etc.
  • Rate limit login attempts to prevent brute force
  • Log auth events for audit trails and anomaly detection

📋 Key Takeaways — Step 2

  • Two auth options: Keyauth (fast, commercial, HWID locking) or Self-hosted Node.js (free, full control, JWT-based)
  • Keyauth: Drop-in DLL/SDK for C# and C++ — handles licensing, HWID, expiry automatically
  • Self-hosted: Express + bcrypt + JWT — you own the data, but must secure the server yourself
  • Always use HTTPS, hashed passwords, and token-based sessions
  • Auth is optional for personal tools — focus on features first

📖 What is IL2CPP?

IL2CPP (Intermediate Language To C++) is Unity's scripting backend that converts C# game code into native C++ before compilation. It improves performance, security, and memory management. Dumping IL2CPP means recovering the original C# signatures, types, methods, and metadata — effectively giving you a client-side source code representation.

ℹ️
Manual approach: You can dump memory manually and search for ELF or Global-Metadata headers manually if you want — the scripts just automate this process.

📋 Prerequisites

  • Root access (Magisk recommended)
  • Free Fire installed (latest version)
  • GameGuardian installed and granted root permissions
  • Download MetadataSearcher.lua and LibDumper.lua from GameGuardian's website → "Scripts" section or current website's Downloads section

Step 3.1: Bypass Anti-Tamper (Pattern Replacement) Optional

  1. Launch Free Fire and reach the lobby screen.
  2. Open GameGuardian (floating icon).
  3. Select the Free Fire process (com.dts.freefireth).
  4. Go to the Search tab, tap on "Hexadecimal".
  5. Search for this array of byte pattern:
    F0 B5 03 AF 2D E9 00 0F 83 B0 0E 46
  6. When results appear, replace all occurrences with:
    00 20 70 47
⚡
Fallback patterns: If the primary pattern doesn't work, try F0 B5 03 AF 2D E9 00 0F (shorter variant).
Cheat Engine alternative: If GameGuardian is not working for this step, use Cheat Engine instead!

Step 3.2: Find global-metadata.dat in Memory

  1. Open GameGuardian again, go to the "Scripts" tab.
  2. Execute MetadataSearcher.lua.
  3. The script will return one or more addresses. Long-click the result → Copy the address value.
  4. Save this address (e.g., in a text file).
  5. Long-click the same result again → select "Go to address".
  6. Edit the value at that address: change it from 0 to AF 1B B1 FA r (hex bytes).
📝
Note: Sub steps 5 & 6 are sometimes required and sometimes aren't, but it is recommended to go through with them regardless.

Step 3.3: Dump Memory Region

  1. With the same address selected, tap "Dump memory".
  2. Set From = that address, To = the same address (the dumper will auto-expand).
  3. Set Type to Ca: (custom range).
  4. Start the dump. It will create many .bin files in /sdcard/dumps/.

Step 3.4: Identify the Real global-metadata.dat

  1. Use a file manager with root access to navigate to:
    /data/app/com.dts.freefireth-*/base.apk/assets/bin/Data/Managed/Metadata/
    (or extract the APK's assets)
  2. Note the file size (in bytes) of the original global-metadata file.
  3. Go to the dumped memory folder (/sdcard/dumps/).
  4. Sort files by size and find the one that exactly matches the original size.
  5. Rename that file to global-metadata.dat and copy it to your PC.

Step 3.5: Dump libil2cpp.so

  1. Return to GameGuardian, run LibDumper.lua.
  2. Select "Il2Cpp" when prompted.
  3. The script will dump libil2cpp.so (or a similar named file) to storage.
  4. Transfer this file to your PC.

Step 3.6: Run Il2CppDumper

☁️ Option A: Online Dumper (Easiest) ▼
  1. Go to il2cppdumper.com.
  2. Upload your libil2cpp.so (or GameAssembly.dll etc.) as IL2CPP Binary.
  3. Upload your global-metadata.dat.
  4. Click Dump. The server processes the files and returns a ZIP containing dump.cs, script.json, etc.
💻 Option B: Command Line (Windows/Linux) ▼
Bash — Il2CppDumper CLI
Il2CppDumper.exe <libil2cpp.so> <global-metadata.dat> <output_directory>

# Example:
Il2CppDumper.exe libil2cpp.so global-metadata.dat ./dump_output
🖥️ Option C: GUI Version ▼
Download the GUI version of Il2CppDumper and load both files through the graphical interface. Easiest for Windows users who prefer not to use the command line.

🔧 Troubleshooting

ProblemSolution
Game crashes after pattern replacementRestart game and repeat steps quickly before anti-tamper re-activates
MetadataSearcher.lua returns no resultsEnsure you performed the pattern replacement and entered the main lobby. Try different pattern offsets.
Dumped memory file size does not matchTry again or try to dump a slightly larger range (From = address - 0x1000, To = address + 0x1000) then search for correct size
Il2CppDumper fails ("invalid metadata")You have the wrong global-metadata.dat; repeat Step 3.4 with stricter size matching
No libil2cpp.so in dumpRun LibDumper.lua as root and select the correct region. You can also copy it directly from /data/app/.../lib/arm64/ if not protected

💡 Tips for Success

✅

Recommended Setup

  • Use an emulator (LDPlayer, Nox) with rooted Android 7-9 for easier debugging
  • Disable all other memory scanning tools to avoid conflicts
  • For Android 10+, use a Magisk module like LSPosed with RootNativeBridge to bypass additional protections
⚠️

Common Pitfalls

  • If the game detects GameGuardian, hide it via MagiskHide or use Memory Editor (another tool)
  • Don't skip the anti-tamper bypass — it's optional but dramatically improves success rate
  • Always compare file sizes carefully in Step 3.4 — a wrong match = invalid dump
